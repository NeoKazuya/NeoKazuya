# Weekly build log

The card is generated by `scripts/activity.py` with Python 3.9+ and GitHub CLI. No third-party Python packages are needed. Both light and dark SVGs are generated. README picks the matching theme.

## Automatic refresh

The GitHub Actions workflow runs daily at 15:23 UTC and supports manual runs. Add a repository Actions secret named `PROFILE_READ_TOKEN` containing a GitHub credential authorized for the repositories being counted:

- The credential must cover all contributing repositories, including collaborator and organization repositories. A single fine-grained token is scoped to one resource owner, so it may not cover this account-wide view. Use an appropriately authorized GitHub App or token strategy spanning those owners.
- Repository access: all contributing repositories, not only personally owned repositories.
- Repository permissions: Contents **read**, Pull requests **read**, Metadata **read**.
- No write permissions are needed for this token. The workflow's built-in token writes only to this profile repository.

Do not put the token in a file, README or chat. Missing/expired credentials cause the run to fail and preserve the previous card. GitHub can disable scheduled workflows in inactive public repositories after 60 days; re-enable the workflow in Actions if needed.

## Local refresh

With GitHub CLI signed in:

```
python3 scripts/activity.py
```

The collector fully paginates responses, counts only the configured account’s activity, and emits only approved aggregate fields. `activity.json` contains all active project names, descriptions and counts. All accessible owned, collaborator and organization repositories are considered, plus upstream repositories discovered from authored merged PRs and commit search; edit `collect()` to narrow that scope later. Forks count activity authored by the configured user; identical commits in different repositories count once per repository, not globally.

Zero-activity projects do not appear. No activity produces a zero-total empty state. Failed fetches preserve the prior published cards. Default-branch commit counting is intentionally explicit: squash merging can produce fewer commits than a feature branch contained.

## Counting rules

The past seven calendar days including today in America/Los_Angeles. Includes activity authored by NeoKazuya across accessible owned, collaborator, organization and discovered public upstream repositories. The profile repository is excluded. Only projects with merged PRs or default-branch commits in the window appear. Top three: merged PR count, then commit count, then project name.

PRs are authored by this account and merged during the window. Commits are authored by this account and reachable on each repository’s default branch, with committer timestamps in the window. Unmerged feature-branch commits, reviews and issues are not part of these two metrics. PRs and commits overlap and are never added into a combined score. Access restrictions and GitHub search indexing can limit discovery of external upstream work. Incomplete search results fail the refresh rather than publish a partial report.

Names and GitHub descriptions are used as provided (long descriptions are shortened on the image). No code, commit messages or PR titles are published. The card timestamp is the last successful refresh.
